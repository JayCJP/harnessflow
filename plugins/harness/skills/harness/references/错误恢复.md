# 错误恢复（advance-phase 失败时按需读取）

> 本文件从 `harness/SKILL.md` 外移（渐进式披露）。仅当 `advance-phase.js` 推进失败时读取。

**不需要决策树。** `advance-phase.js` 返回 `success: false` 时**一律回 Step 1**：
重新执行 `dispatch.js`，由它按 `status` 给出 `recovery.command`。

```
advance-phase.js 失败
  └─ 回 Step 1 → dispatch.js
       ├─ status=fix_loop  → recovery.command（--fix-loop）原样执行 → 再回 Step 1
       ├─ recovery.command 存在 → 原样执行 → 回 Step 1
       └─ recovery.command 为 null → 转人工，转述 recovery.description 给用户
```

`advance-phase.js` **不输出任何命令** —— 命令信源唯一是 `dispatch.js` 的
`recovery.command`（其中 `--fix-loop` 那条由 `policy.js` 的 `_meta.fixLoopHint` 生成，
dispatch 原样转发）。主 Agent 自行拼 `--fix-loop` 属于判断权回流。

恢复策略（fix-loop / 转人工）由 `policy.js` 按 `recovery level` 判定：
2=提示修复、3=降级、4=人工。主 Agent 不参与选择。

> 注：level 1（自动修复）当前无条目 —— 历史上的 3 个 `autoFix` 触发条件与修复条件互斥、
> 永不执行，已连同 `--auto-fix` flag 与 `attemptAutoRecovery` 一并删除。
> 门控失败不存在「自动修一下再重试」的通道，只能按 `resolution` 修好后重跑。

## advance-phase.js 输出解读

**只看 `success` 一个字段**，不要解析其余内容。它只报「推进了没有 / 门卡在哪」，
**不含任何 Spawn 信息**（没有 `agentPrompt` / `nextAgent` / `expectedOutputs`）。

```
success: true   → 回 Step 1 重新 dispatch.js（新 Phase 的指令由它给出）
success: false  → 回 Step 1 重新 dispatch.js（recovery.command 由它给出）
```

失败时输出里要看的只有 `structuredBlockers[]` 的 `resolution`（怎么修）与
`recoverySuggestions`（policy 提示）。修完后**不要直接重跑 advance** ——
回 Step 1 让 dispatch 重新裁定该推进还是该重做。

Spawn 只用 `dispatch.js` 的 `nextAgent` + `agentPrompt`：
`agentPrompt` 已经是完整可原样传入的 prompt（摘要路径、契约清单、教训、约束都在里面），
主 Agent **不拼装、不补充、不改写**。

## 三类特殊拒绝

| 拒绝原因 | 含义 | 处理 |
|---------|------|------|
| targetPhase 非法（越界 / 跨阶 / 倒退） | 脚本独立校验入参，主 Agent 传错也写不坏状态 | 用 `dispatch.js` 的 `advanceCommand`，不要手写 targetPhase |
| `phase_integrity_violation` | 某 Phase 已标 completed 但 `state.phase` 仍在其之前 → 判定为有人绕过脚本改了状态 | 按输出的人工修复指引处理，事件已写入 trace |
| 归档守卫 | Story 已归档，禁止 `--rollback` / `--fix-loop` | 先 `archive-story.js <id> restore` 复档 |

## fix-loop 用尽预算

review 与 test **各 2 轮独立预算**。用尽后 `dispatch.js` 输出 `status: blocked`
且 `recovery.command` 为 `null` → 转人工，把 `recovery.description` 转述给用户。

门控失败的**逐 Phase 细节**（哪些检查、什么级别、怎么改）见 `phases/phase-N.md`。
